# 直播监测

实时监测主播开播情况的 Windows 桌面软件。打开软件后自动在后台定时检测你添加的直播间，主播一开播立即弹出置顶小窗 + 提示音，一键打开网页版直播间。

## 特点

- **自定义直播间**：支持 斗鱼 / 虎牙 / B站 / 抖音 / 快手，粘贴直播间链接或直接输入房间号即可添加
- **自动监测**：启动即开始后台轮询（默认每 30 秒），无需任何手动操作；网络波动时保持上次已知状态，不会误报
- **开播提醒**：检测到开播 → 右下角弹出置顶提醒小窗（**不抢占焦点**，不打断游戏/工作）+ 提示音。窗口**常驻显示直到你手动操作**，弹窗未关时提示音默认每 60 秒温和重复一次
  - 「打开直播间」一键直达网页版
  - 「忽略」关闭本次弹窗（下次开播仍会提醒）
  - 「不再提醒」本次开播不再提醒（主播下播后自动恢复）
- **状态记录**：每个直播间的状态、直播标题、**所在分区**、最后检测时间、**上次开播时间**都会记录并保存，重启软件后自动恢复显示；直播中的房间整行绿色高亮，与未开播一眼区分
- **分区监测**：列表新增「分区」列，实时显示主播当前直播分区（如 `最终幻想14`；**优先显示小类，没有小类时显示大类**）；分区发生变化时会写入日志，开播提醒弹窗里也会显示分区
- **极致轻量**：原生 C# WinForms 程序，无任何第三方依赖，空闲 CPU ≈ 0%，内存约 30~40 MB，可最小化到托盘静默运行
- **长时间运行稳定**：检测线程异常自愈、计时器全部释放、配置文件原子写入（断电不损坏，带备份恢复）、日志轮转保留上一份、每小时自动记录自身资源占用（便于排查长跑问题）
- **简洁干净**：白底黑字田字格图标、扁平化浅色界面
- 关闭主窗口自动最小化到托盘继续监测

## 使用方法

1. 双击运行 `dist\直播监测.exe`（首次运行可能在窗口右下角被 SmartScreen 提示，点「更多信息 → 仍要运行」即可）
2. 点击右上角 **「+ 添加直播间」**，粘贴直播间链接或输入房间号 → 软件自动识别平台和主播 → 点「添加」
3. 完成。之后主播开播时自动弹窗提醒。建议点「设置」按需调整检测间隔（默认 30 秒）

> 配置文件 `config.json` 自动生成在程序同目录（无权限时位于 `%APPDATA%\LiveMonitor`），绿色便携，删除即恢复出厂。
> 保存配置采用「临时文件 + 原子替换 + `.bak` 备份」；主配置损坏时会自动隔离成 `config.json.bad-时间戳` 并尝试从备份恢复。

### 托盘菜单

右键任务栏托盘图标：显示主界面 / 暂停监测 / 立即检测 / 退出。

### 设置项

- 检测间隔（15~3600 秒，默认 30）
- 提示音开关、**循环提示间隔**（默认 60 秒；弹窗显示期间每隔 N 秒重复一次，**关闭弹窗即停止**）、试听
- **自定义提示音**：支持选择 wav/mp3 音频文件（留空使用内置提示音），试听按钮预览当前选择
- **自动打开直播间**：勾选后，检测到开播先弹窗+提示音，3 秒后自动打开直播间网页并关闭弹窗（提前点击任意按钮则按你的操作执行）
- **弹窗自动关闭**（默认 0 = 常驻显示直到手动操作；设为 N 秒则自动关闭）
- 启动时对已在直播的房间是否也提醒
- 关闭主窗口时：最小化到托盘 / 直接退出

### 列表右键菜单

打开直播间 / 立即检测该房间 / **开/关该主播的开播提醒**（对应列表「提醒」列）/ 复制链接 / 删除。

## 状态图标含义

- 🟢 **直播中**（整行浅绿高亮；B站轮播显示「轮播中」）
- ⚪ 未开播
- 🟠 直播中(异常)/未开播(异常)：最近一次检测网络失败，显示上次已知状态，网络恢复后自动修正
- 🔴 房间不存在 / 检测失败
- 列表记录「最后检测」「上次开播」和「分区」——**上次开播优先取平台返回的真实开播时间**（如 B站直播页面的 `live_start_time`），并过滤明显异常的时间；列表中**只显示月日**（`MM-dd`，不显示具体时分，避免平台时间轻微偏差让人觉得"记录不对"）。部分平台本身不提供开播时间时，按检测到开播的时间记录（同样只显示月日）

## 技术说明

- 无第三方依赖：仅用 Windows 自带 .NET Framework 4.8 的 `csc.exe` 编译，任何 Win10/11 可直接运行
- **合规低风险检测**：B站优先读取公开直播间网页（与正常浏览器访问完全相同），接口仅作备用；单线程顺序轮询、默认 30 秒间隔（最短 15 秒）、请求前自动预热浏览器 Cookie，避免触发平台风控
- 单后台线程 + 事件等待轮询（等待期间零 CPU）；HTTP 连接复用；检测失败不影响其他房间；后台线程每轮都有异常兜底，单次异常不会让监测静默停止
- **程序本身是纯托管进程**：与 Windows 资源管理器（explorer.exe）是隔离的两个进程，不注入 DLL、不写注册表钩子；对系统外壳的交互只有托盘图标、打开浏览器、剪贴板这些常规 API，且托盘文本仅在内容变化时才真正通知外壳
- 图标资源符合 Windows ICO 规范：16/20/24/32/40/48/64 使用 32bpp BMP 条目、仅 256x256 使用 PNG（避免旧 GDI/外壳代码路径对 PNG 小图标的兼容问题）
- 打开直播间只允许 `http/https` 地址（配置被手工改坏也不会触发本地程序启动）
- 日志：`dist\logs\app.log`（超过 1MB 自动轮转为 `app.prev.log`，保留上一份），记录每次检测结果与状态切换；**每小时追加一条 `health:` 资源占用行**（GDI/USER/句柄/内存/线程/房间数），长时间运行后出问题可直接查看趋势；程序检测到资源管理器重启（TaskbarCreated）时也会记录一行
- 自诊断：`dist\LiveMonitorTest.exe` 离线运行 **79 项**解析/配置/资源/图标/稳定性自测，结果写入 `dist\selftest_result.txt`
- 环境诊断工具：`tools\diagnose-explorer-crash.ps1` 可收集 explorer.exe 崩溃/GDI 泄漏证据并（可选，需管理员）开启 explorer 崩溃转储，详见下文

## 常见问题

1. **状态显示「直播中(异常)」/「未开播(异常)」**：最近一次检测网络失败或平台限流，软件保持上次已知状态并显示橙色提示；连续 2 次检测失败才会切换为「检测失败」。网络恢复后自动修正
2. **为什么有时检测到开播不立刻弹窗**：连续 2 次确认机制与弹窗冷却时间（同一主播 3 分钟内只提醒一次）用于过滤平台接口抖动和主播反复上下播，避免误报轰炸
3. **抖音显示「接口受限」**：抖音风控较严，先手动用浏览器打开一次该直播间再重试；仍失败则先不添加（软件会持续重试）
4. **虎牙偶尔检测失败**：虎牙网页偶发反爬拦截，下一轮会自动恢复
5. **双击行 / 右键菜单**：打开网页直播间、立即检测该房间、开/关该主播的开播提醒、复制链接、删除
6. **排查问题**：每次检测结果和状态切换都记录在 `dist\logs\app.log`（UTF-8，用记事本打开），历史在 `app.prev.log`；每小时还有 `health:` 行。反馈问题时请附带这两个文件
7. **修改后如何重新打包**：`build\build.ps1` 自动生成图标、提示音并编译（需要 Windows 自带的 .NET Framework 编译器，无需安装任何 SDK）
8. **Windows 弹出「explorer.exe - 系统错误：系统在此应用程序中检测到基于堆栈的缓冲区溢出」**：
   这是 **Windows 资源管理器自己崩溃**（`0xC0000409` fail-fast，随后桌面/任务栏会闪一下并被系统重启），**不是本程序引起的**：
   - 本程序是独立进程，不可能改写 explorer.exe 的栈；本机实测本程序 GDI 对象 43 个、内存 52MB、句柄约 600，长时间运行稳定；而该错误在本程序存在之前（2025 年）就已经在日志里出现过。
   - 真正原因通常是 **explorer.exe 加载的第三方外壳扩展（shell extension）泄漏 GDI 位图/字体**，数量逼近 Windows 每进程 10000 的配额后，explorer 主动 fail-fast。本机已定位到高危嫌疑：**Internet Download Manager（IDM）**——官方 6.43 Build 5 更新日志明确写了 "Fixed a bug that sometimes caused Windows Explorer to crash"，而本机 IDM 版本早于该修复，且 explorer 里还加载着 2021 年的旧版 `IDMShellExt64.dll`。
   - 处理顺序：① 把 IDM 升级到 **6.43 Build 5 或更新版本**（火绒/QQ/百度网盘/Bandizip/Adobe 等带右键菜单或图标叠加的软件也建议升级到最新版）；② 运行下面的取证脚本收集证据；③ 仍复现则用 `Autoruns`（微软官方工具）临时禁用第三方 shell 扩展做二分对照；④ 用管理员 PowerShell 执行 `sfc /scannow` 和 `DISM /Online /Cleanup-Image /RestoreHealth`。
   - 取证脚本（只读收集，不会改动系统）：
     ```powershell
     powershell -NoProfile -ExecutionPolicy Bypass -File tools\diagnose-explorer-crash.ps1
     ```
     如需抓取下一次崩溃的转储（需管理员，可精确定位到具体扩展 DLL）：
     ```powershell
     powershell -NoProfile -ExecutionPolicy Bypass -File tools\diagnose-explorer-crash.ps1 -SetupDumps
     ```
     详细分析见 `docs\explorer-crash-analysis.md`。
9. **「上次开播」时间看着不对 / 只显示月日**：不同平台的开播时间字段精度和时区都不一样，个别页面还会给出缓存/异常值，因此记录时优先取平台返回的真实开播时间并过滤明显不合理的时间（未来时间、过旧时间），**列表只显示月日**、不显示时分，避免"看起来精确但其实差几分钟"的困扰。对不提供开播时间的平台（如虎牙/抖音部分接口），按软件检测到开播的时间记录。若发现某天日期明显错误，把 `app.log` 里对应房间的 `start=` 行发出来即可定位。
10. **「分区」列显示 — 或和平台网页上不一样**：分区来自平台页面/接口的公开字段（B站 area_name/parent_area_name、斗鱼 cate_name、虎牙 gameFullName 等）；平台未返回或该平台不提供时会显示「—」，网络异常的一轮不会清空已有分区。

## 目录结构

```
live-monitor/
├── dist/直播监测.exe     # 主程序(交付文件)
├── dist/LiveMonitorTest.exe  # 离线自测工具
├── src/                 # C# 源码
├── build/               # 构建脚本(图标/提示音/编译)
├── res/                 # 生成的图标与提示音
├── test/                # 自测代码
├── tools/               # 诊断脚本(diagnose-explorer-crash.ps1)
└── docs/                # 分析文档(explorer 崩溃根因分析)
```
