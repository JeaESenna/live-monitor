# 威胁模型（Android 版）

> 状态：阶段一文档（2026-11-13），基于当前最新源码（`android/app/src`）与构建配置。
> 方法：资产/信任边界建模 + STRIDE + 移动端攻击面逐项检查；风险等级 = 可能性 × 影响（高/中/低）。
> 验证方式中标注「静态」「单测」「APK 扫描」「人工评审」「动态验证」；阶段三动态测试由 Lead 在 LDPlayer 14（Android 14/API34 模拟器）执行、本评审员核验证据（截图/命令输出摘录），**未独立复跑**；模拟器覆盖边界见第 7 节与 `安全测试报告.md` 第 8.5 节。

## 1. 范围与假设

**在范围内**：
- App 进程与本地数据（SharedPreferences、日志）、前台服务、通知、5 平台网络访问、构建与交付 APK。
- 攻击者能力假设：本机其他普通 App、恶意网页/恶意平台响应、被篡改的配置文件、物理接触（未 root/已 root 分别考虑）、供应链（依赖/镜像）。

**不在范围内（或明确接受）**：
- 系统级 root/内核攻击、物理取证、平台服务端安全、运营商网络攻击。
- 直播平台自身的账号/风控体系（本 App 不登录、不携带账号 Cookie）。
- 用户自行二次打包/重签名后的产物（签名一旦更换即不在交付范围）。

**关键安全假设**：
1. 系统 CA 整体可信但**不信任用户安装的 CA**；此外对平台域名启用 **CA 家族级证书固定**（GlobalSign/DigiCert），把信任范围进一步收窄（见 5.3 与 5.13）。
2. 平台公开页面/接口返回数据视为**不可信输入**（可能被中间人、平台错误、缓存污染影响）。
3. 本地配置可能被 root/备份/手动修改，因此读取时必须重新校验（尤其是 URL）。
4. 交付 APK 由项目方本地 keystore 签名（v2+v3、非 debug 证书），安装前应核对签名/哈希；密钥管理责任见 5.8。

| --- | --- | --- |
| 房间列表 | 用户主动添加的直播间标识、备注、状态、标题、分区、开播时间 | 中（反映观看偏好，可能含用户备注中的个人信息） |
| 设置 | 检测间隔、提示音、自动关闭、监测开关 | 低 |

| 交付 APK 与签名 | 用户安装的二进制 | 高（被篡改即全盘失陷） |
| 用户信任/合规声誉 | 商店/用户对“无上报、最小权限”的信任 | 高（无形资产） |

## 3. 信任边界

```
[不可信] 用户输入（粘贴链接/房间号）
   │  ① parseInput/ID 正则/控制字符过滤/URL 重建
   ▼
[可信] 规范 (platform, id, https URL) ──► SharedPreferences（可能被 root/备份篡改）
   │  ② 读取时 normalizeStoredUrl：https+443+精确域名+路径匹配 id
   ▼
[可信] PlatformApi.check ──► HttpFetcher（每次请求/每跳重定向 ③UrlPolicy 校验；④TLS 1.2+ + CA 家族级证书固定）
   │  ⑤ 平台响应（不可信：超大、畸形、恶意 HTML/JSON、重定向、限流、被劫持的证书）
   ▼
[不可信输入] PlatformParsers（防御性解析 + 清洗限长）──► 状态机 ──► 通知/UI/持久化
   │
   ├─⑥ 通知系统（锁屏可见性、其他 App 读取通知、PendingIntent 动作）
   ├─⑦ 其他应用（显式/隐式 Intent、组件导出、UI 欺骗）
   ├─⑧ 本地存储/日志/自定义音频（备份、剪贴板、诊断界面、SAF 导入文件）
   ├─⑨ 外部 App/浏览器（v1.1.1：平台 App deep link、https 浏览器打开；不再有应用市场/官网下载；隐式浏览器 Intent 可能被同名 handler 劫持）
   └─⑩ 构建/依赖/签名/密钥管理（Gradle 仓库、依赖包、keystore、签名密钥备份包、分发渠道）
```

## 5. 移动端攻击面逐项分析

### 5.1 组件导出与 Intent 注入

- **现状**：`AndroidManifest.xml` 仅 `.ui.MainActivity` 导出（MAIN/LAUNCHER）；`MonitorService` `exported=false`；无 receiver/provider。
- **MainActivity 被外部显式拉起**：外部 App 只能启动界面，不能传入被 App 使用的 URL/房间参数（Activity 不读取 Intent extras，无 `getIntent()` 数据处理逻辑）；界面只能由用户本人操作。
- **命令通道**：UI 与服务之间使用显式 Intent（`Intent(context, MonitorService::class.java)`），无隐式广播/无 action 字符串外部可达。
- **验证**：源码扫描 + APK xmltree（`components.exported`、`components.main_filter`）。状态：✅。

### 5.2 通知隐私与锁屏泄露

- 提醒通知内容：主播显示名、平台、分区、直播标题（均来自平台公开页面，已清洗限长）。
- 两个渠道均 `VISIBILITY_PRIVATE`；提醒通知 `setVisibility(PRIVATE)`，锁屏默认显示“内容已隐藏”（用户可在系统里改成显示/完全隐藏）。
- 常驻服务通知 `IMPORTANCE_LOW` 静音；提醒通知 `IMPORTANCE_HIGH`。
- 通知点击只打开本 App；`setDeleteIntent`/动作均为 `FLAG_IMMUTABLE` 显式 PendingIntent。
- **残余**：用户若在系统设置里把本 App 通知设为“显示全部内容”，锁屏会显示标题——这是用户选择，App 无法强制；可考虑后续提供“锁屏隐藏标题”开关（未实现）。
- **验证**：源码扫描 `code.notification_privacy` + APK 检查；锁屏实际表现需真机（未执行）。

### 5.3 明文与 TLS / 证书信任 / MITM

- `usesCleartextTraffic=false` + `network_security_config.xml`：`cleartextTrafficPermitted=false`，仅信任 `system` CA，**不信任用户安装的 CA**（降 MITM 风险，也阻断了常规抓包调试）。
- 代码层 `PlatformUrlPolicy` 再校验 `isHttps` + 端口 443 + 域名白名单（纵深防御，覆盖每一跳重定向）。
- 未使用自定义 `TrustManager`/`HostnameVerifier`/`sslSocketFactory`（扫描无命中）；TLS 最低版本 TLS 1.2（`ConnectionSpec.MODERN_TLS`）。
- **严格 TLS 证书固定**（默认关闭，可手动开启，详见 5.13）：只接受平台证书链属于 GlobalSign（斗鱼/B站/快手）或 DigiCert（虎牙/抖音）CA 家族的证书。
- **验证**：APK NSC 内容检查 + 源码 `code.tls_bypass`/`code.tls_pinning`/`code.cleartext_http` 扫描 + TlsPolicyTest + LDPlayer 实网证书链验证。状态：✅。

### 5.4 日志泄露

- `AppLog`：应用私有目录、1MB 轮转 + 1 份历史；只记录平台 key/房间 id/状态/简短错误；**不记录 URL/标题/Cookie/页面内容**；`sanitize` 先做 URL/凭据脱敏再剔除控制字符（纵深防御）。
- 诊断界面：用户可查看最近 200 行、主动复制、清空；复制是用户主动行为。
- **验证**：源码扫描 `code.log_leak`、`code.applog_redaction`；日志实际内容需真机运行后抽查（未执行）。

### 5.5 配置篡改/注入

- 持久化 URL 读取时必须通过 `normalizeStoredUrl`：https、443、无账号密码、**精确平台域名**、路径与 id 匹配；非法条目直接丢弃。
- 所有展示字段读取时 `sanitizeText` 清洗控制字符并限长；设置值 `normalize()` 做范围收敛（间隔 15–3600、循环 0–3600 等）。
- 房间数上限 200、重复 key 去重；JSON 解析异常回退备份/默认值。
- **验证**：单测 `UrlWhitelistTest`/`InputParserTest` + 仓储单测；静态扫描。状态：✅。

### 5.6 恶意/异常平台响应与解析器健壮性

- 所有返回视为不可信：`HttpFetcher` 限制响应体 3MB、整体 15s 超时、重定向 5 跳逐跳校验；解析器对字段缺失/类型错误/截断返回 null 或空字段，不抛异常；正则带长度上界；展示字段统一 `PlatformText.displayText` 清洗。
- 状态机：不可靠结果连续 2 次才覆盖已知状态，网络异常轮次不清空标题/分区；连续失败退避。
- **验证**：`PlatformParsersTest`/`HttpFetcherTest`/`MonitorEngineTest` 单测（JVM，已纳入 `run-security-tests.ps1`）；静态扫描明文/动态加载等。
- **残余**：平台页面结构变化会导致解析失败（显示“检测失败/网络异常”而非误报），需随平台更新维护正则；无 fuzz 测试（可后续补充）。

### 5.7 依赖与供应链

- 依赖固定版本：AndroidX（core-ktx 1.15.0 / lifecycle 2.8.7 / activity-compose 1.9.3 / Compose BOM 2024.12.01）、OkHttp 4.12.0、Coroutines 1.9.0、测试库 JUnit 4.13.2 / MockWebServer / org.json；无统计/广告/推送 SDK；R8 minify + shrinkResources。
- Gradle wrapper 配置了 `distributionSha256Sum`；但**未启用** `gradle/verification-metadata.xml` 依赖校验，仓库优先阿里云镜像（国内下载速度原因）。
- **缓解建议**：CI/发布机构建切换官方源（google/mavenCentral）优先；生成并提交 `verification-metadata.xml`；定期用依赖漏洞库（如 OWASP Dependency-Check/Gradle versions plugin）复核版本，尤其 OkHttp/Coroutines/AndroidX。
- **验证**：`run-security-tests.ps1` 输出 `:app:dependencies --configuration releaseRuntimeClasspath` 清单 + 静态扫描第三方 SDK 痕迹。状态：⚠️ 残余风险（已记录，不阻塞交付）。

### 5.8 签名与更新

- 交付 APK 已使用本机 keystore 签名：**v2+v3、v1=false、RSA 4096-bit、非 debug 证书**（DN `CN=LiveMonitor Android…`），已实际安装运行；debug 测试包使用公开 debug 证书（debuggable，仅本机试用、禁止分发）。
- `check-apk-hardening.ps1` 对签名（v2/v3、v1、debug 证书、密钥长度、证书 DN）自动检查并给出 PASS/WARN/FAIL；SHA-256 与随附 `.sha256`、发布说明三方核对。

### 5.10 无障碍 / 悬浮窗 / 重定向 / SSRF

- 无 `BIND_ACCESSIBILITY_SERVICE`、无 `SYSTEM_ALERT_WINDOW`、无 `MediaProjection`、无 `BIND_NOTIFICATION_LISTENER_SERVICE`、无 `BIND_DEVICE_ADMIN`（权限清单 + dex 扫描）。

- **验证**：源码扫描 `code.battery_whitelist_api`（当前 PASS：未直接请求）+ APK dex 扫描。状态：✅。

- **剪贴板**：仅在用户点击“复制日志”时写入；无读取剪贴板代码（粘贴到输入框由系统 IME 完成，App 不调用 `ClipboardManager.getPrimaryClip`）。
- **通知动作输入**：`EXTRA_ROOM_KEY` 来自本 App 自己的 PendingIntent，服务侧再校验非空；即使被塞入任意 key，也只会触发取消通知/清 mute，无提权。
- **文件/存储**：无外部存储权限；提示音为 `res/raw/chime.wav` 内置资源；日志/配置均在应用私有目录。
- **网络状态查询**：`ACCESS_NETWORK_STATE` 只读，无敏感信息。

### 5.13 TLS 证书固定（MITM / CA 攻击面）

**威胁**：设备被预置/安装恶意根证书、CA 被攻破、或用户处于恶意代理环境时，攻击者可对平台域名做中间人，伪造“开播/未开播”检测结果，或利用响应内容触发解析器缺陷。

**缓解（已实现）**：
- `TlsPolicy`：对 10 个允许请求的平台 host 固定 CA 家族（GlobalSign 5 个 pin、DigiCert 4 个 pin，均为**中间证书+根证书 SPKI**，2026-11-13 实测抓链获取）；`CertificatePinner` + `ConnectionSpec.MODERN_TLS`（TLS1.2+）。
- pin 命中链上任意证书即通过（容忍叶子证书轮换）；`SSLPeerUnverifiedException` 归类 `POLICY` 并提示“TLS 证书固定校验失败，可能存在中间人劫持”。
- 默认关闭（兼容华为/卓易通等环境）；设置页提供“严格证书固定”开关，可手动开启或作为平台换 CA 的逃生口（关闭仍有 HTTPS + 系统 CA + 域名白名单约束）。
- 运行期切换：`PlatformHttp.pinningEnabled` 变化时 `PlatformCheckers` 重建检测器并换用对应 OkHttpClient；App 启动与设置变更均应用。
- 验证：`TlsPolicyTest`（5 项：host 全覆盖/pin 格式长度/CertificatePinner 生效/关闭不固定）、源码与 APK 静态扫描（9 个 pin + 失败文案）、**LDPlayer 实网**：pinning 开启时斗鱼/B站（GlobalSign 链）、虎牙（DigiCert/GeoTrust 链）真实检测成功；关闭/再开启切换正常。抖音/快手未找到真实房间，按同 CA 家族抓链覆盖，建议后续补测。

**边界与残余风险（重要）**：
- 固定的是 **CA 家族**，不是叶子证书/单一公钥：同一 CA 家族下被错误签发的证书仍可能通过 pin；更高保证需固定叶子 SPKI（但会随 CDN 轮换频繁失效，需权衡）。
- **pin 维护责任**：平台若整体更换 CA（如改用 Let's Encrypt），检测会失败（归类 POLICY，不误报开播状态），需更新 pin 或用户临时关闭开关；pin 应随平台证书变化复核。
- **pinning 不提供匿名性**：直连平台仍暴露客户端 IP，隐藏 IP 只能由用户使用 VPN/代理（本 App 不内置代理、不做 IP 轮换，符合合规要求）。
- 无法防御“已 root + 植入系统 CA + 同时绕过 pin/改包”的极端设备；也不防御平台服务端自身被攻破。
- 禁用 pinning 的用户设置会降低 MITM 防护，属用户自主选择的逃生口（文档/设置文案已说明）。

### 5.14 外部 App / 网页跳转与 Intent 劫持（v1.1.1）

**威胁**：用户点击“进入直播间 / 浏览器打开网页版”时：
1. 目标 URL 可能被外部 Intent 注入（例如从通知/Activity extras 携带任意 URL）；
2. 隐式 `https` ACTION_VIEW 可能被已安装的恶意 App 注册同名 handler 劫持，展示钓鱼页；
3. 跳转 Activity 若被导出，可被外部拉起并构造参数；
4. 自动打开（后台 `startActivity`）可能被滥用为“后台拉起外部应用”或造成刷屏。

**缓解（已实现，v1.1.1 已下架“下载 App”进一步缩小攻击面）**：
- `RoomJumpActivity` `exported=false`、`noHistory`/`excludeFromRecents`；只接收本地房间 key（`RoomJumpIntent`），从仓储重新查询房间，**不接受外部 URL/data**（源码规则 `code.jump_intent_contract` PASS）。
- 跳转目标全部来自 `JumpTargets`：`webUrl` 由 `PlatformApi.normalizeStoredUrl` 重新校验（https/443/平台精确域名/路径含 id）；deep link 由固定模板+已校验 roomId 拼接；**不再有应用市场 URI、官方下载页 URL/包名常量**（`code.download_removed` PASS）。
- 平台 App 跳转全部 `Intent(...).setPackage(平台包名)`；打开 App 首页用 `getLaunchIntentForPackage`（显式包名）；每个 `startActivity` 加 `FLAG_ACTIVITY_NEW_TASK` 并 catch `ActivityNotFoundException/SecurityException/AndroidRuntimeException`（`RoomLauncher.tryStartActivity`）。
- **残余（低）**：`openWeb` 先 `resolveActivity` 取系统默认 handler 再 `setPackage` 显式启动；仅解析不到 handler 时回退标准隐式启动。Manifest `<queries>` 只保留 5 个平台包 + https VIEW intent（浏览器解析），**无 market/应用市场查询、无 `QUERY_ALL_PACKAGES`**。
- Android 10+ 后台启动 Activity（BAL）限制：自动打开可能被系统静默拦截（见 5.16）。

**验证**：源码规则（`code.external_intent_package`/`code.hijackable_intent`/`code.jump_intent_contract`/`code.jump_url_allowlist`/`code.download_removed`）、APK 扫描（`components.jump_activity`/`components.deep_link`/`dex.external_intent`/`apk.no_market_download`/`apk.queries`）、动态测试（列表按钮弹窗、通知动作、浏览器分支；v1.1.1 预期弹窗不再有下载按钮）。

### 5.15 自定义媒体文件解析（v1.1.0）

**威胁**：用户通过 SAF 选择的音频文件内容不可信，可能利用媒体解码器漏洞、超大文件占满存储、路径穿越读取应用私有文件、把文件路径写进日志。

**缓解（已实现）**：
- 仅接受 SAF `content://` Uri；**不申请任何存储权限**；不保存/不依赖原始文件名与路径（仅用于推断扩展名）；
- 流式复制到应用内部 `filesDir/sounds/`，强制 **2MB** 上限（声明大小预检 + 流式计数兜底），失败即清理临时文件；
- 固定文件名 `custom_alert.<ext>`（wav/mp3/ogg/m4a/aac），MIME/扩展名双校验；读取时 `canonicalFile` + 父目录校验防路径穿越/符号链接；
- 导入前用 `MediaPlayer.prepare()` 校验可解码（duration>0）；播放只从内部固定目录读取，损坏/不支持时静默回退内置 chime，不影响提醒；
- 日志只记录扩展名/大小，不记录文件名/路径。
- **残余**：MediaPlayer 解析用户音频仍依赖系统解码器（native），无沙箱可隔离 → 2MB 上限 + 内部副本 + 不执行内容，属可接受残余风险。

**验证**：源码规则（`code.custom_sound_safety` PASS：大小上限+内部目录；`code.custom_sound_uri_permission` 无持久化授权）、APK 扫描（`dex.custom_sound`）、动态测试（选择/试听/循环/删除）。

### 5.16 后台自动打开直播间的平台限制（v1.1.0）

- 设置项“开播时自动打开直播间”**默认关闭**（`autoOpenRoom=false`）；仅对手机端新提醒生效，每轮最多排队一次，3 秒后执行，执行前重读设置；服务/通知侧不直接 `startActivity`，统一经 `RoomLauncher.autoOpen`（NEW_TASK+全异常兜底）。
- **Android 10+ 后台 Activity 启动限制（BAL）**：App 在后台时启动 Activity 可能被系统**静默拦截**（不抛异常），因此自动打开不保证生效；实现只记录结果、绝不重试/刷屏，失败不影响监测与通知。
- **残余（SEC-103）**：自动打开在后台/部分 ROM 上可能“日志显示已执行但实际未打开”；建议动态测试分别验证 App 在前台/后台两种场景，并在用户文档说明限制；不申请 `SYSTEM_ALERT_WINDOW` 等权限绕过限制。

**验证**：源码规则 `code.auto_open_default`（PASS：默认 false）、`code.auto_open_guard`（PASS：经 RoomLauncher 统一封装）、动态测试（自动打开默认关；开启后前后台行为）。

### 5.17 包可见性（v1.1.1）

- Manifest `<queries>` **只声明 5 个平台包**（air.tv.douyu.android / com.duowan.kiwi / tv.danmaku.bili / com.ss.android.ugc.aweme / com.smile.gifmaker），另仅保留 **https VIEW intent**（用于解析系统默认浏览器并显式启动）；**不申请 `QUERY_ALL_PACKAGES`**；不查询 5 个包以外的应用。
- **v1.1.1 已移除 market VIEW intent 与市场解析代码**（`queryIntentActivities`/`knownMarketPackages` 均已删除）。
- 打开平台 App 只用显式包名（`setPackage`/`getLaunchIntentForPackage`）；浏览器先 `resolveActivity` 再 `setPackage`。
- **验证**：源码规则 `src.manifest.queries`/`code.package_visibility`/`code.download_removed`、APK 扫描 `apk.queries`/`permissions.query_all_packages`/`dex.query_all_packages`/`apk.no_market_download`。

## 6. 风险汇总与处置

| 等级 | 数量 | 项目 |
| --- | --- | --- |
| 高 | 0（已知） | — |
| 中 | 5（已缓解/已记录） | 证书固定为 CA 家族级 + pin 维护责任（平台换 CA 需更新/可临时关闭）；供应链未启用依赖校验/镜像优先；签名密钥管理（本地 keystore + 备份包需离线保管，公开分发建议组织密钥重签）；平台 robots/ToS 合规风险；**后台自动打开受 BAL 限制（SEC-103）** |
| 低 | 5（接受/用户选择） | 锁屏可见性依赖系统/用户设置；截屏无 FLAG_SECURE（接受）；剪贴板为主动操作；pinning 不隐藏 IP / 用户可关闭 pinning；通知渠道迁移丢失旧渠道自定义设置（SEC-104）；自定义音频依赖系统解码器（SEC-106）；**浏览器解析失败时回退隐式启动（v1.1.1 残余，SEC-101 已随下载功能下架进一步缩小）** |

**结论**：代码级高危攻击面（WebView/动态加载/exec/导出 Service/mutable PendingIntent/敏感权限/明文/备份/日志 URL 泄露）均已关闭；主要残余风险来自**交付签名状态**与**供应链完整性**，需在发布流程中解决或明确告知用户。
