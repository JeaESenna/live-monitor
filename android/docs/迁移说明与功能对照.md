# 迁移说明与功能对照（桌面版 → Android）

> 状态：**v1.1.1 文档更新（2026-11-13）**。桌面版基线为 `src/`（C# / .NET Framework 4.8 / WinForms，v1.0.2.2），
> Android 目标为 `android/`（Kotlin 2.0.21 + Jetpack Compose，包名 `com.livemonitor.app`，minSdk 26 / targetSdk 35，当前版本 1.1.1）。
> v1.1.0 按用户需求恢复“进入直播间 / 自动打开 / 自定义提示音”；v1.1.1 按用户要求下架“下载 App”功能。本文描述“移植后的功能边界”，具体实现以当前源码为准；安全测试数据见 `安全测试报告.md`（v3.1）。

## 1. 迁移目标与原则

| 原则 | 说明 |
| --- | --- |
| 提醒为核心 | Android 版核心是“开播状态提醒”；v1.1.0 恢复的“进入直播间/自动打开”均为**用户主动或显式开启**的外跳能力（默认不自动跳、默认不自动打开）。 |
| 最小权限 | 只保留网络/网络状态/通知/前台服务/唤醒锁 6 项权限；无定位、通讯录、短信、存储、相机、悬浮窗、无障碍、开机自启；包可见性只声明 5 个平台包。 |
| 最小数据 | 只在本机保存用户主动添加的房间与提醒所需字段，不登录、不上传、无统计 SDK；自定义提示音只存应用私有目录。 |
| 可预期省电 | 单线程顺序轮询 + 最短 15s 间隔 + 失败退避 + 每次检测短暂唤醒锁，等待期间零 CPU。 |
| 不绕过平台风控 | 只访问 5 平台公开页面/公开接口；不识别/绕过验证码、不使用代理/IP 轮换/UA 轮换、不下载视频流。 |

## 3. 移除/恢复功能的原因与安全/平台限制说明（v1.1.0 更新）

### 3.1 v1.1.0 恢复：进入直播间 / 自动打开（#10/#11/#12）

- **需求变更**：用户明确要求 v1.1.0 恢复“进入直播间”与“自动打开”能力（默认不自动跳、需按钮触发、优先平台 App、未安装 App 时弹窗下载/浏览器）。
- **安全设计**：`RoomJumpActivity` 未导出；只传本机房间 key，从仓储重新查询；URL 仅来自已校验房间数据或固定 https 常量；平台 App 跳转全部 `setPackage`；无 `QUERY_ALL_PACKAGES`（`<queries>` 只声明 5 个平台包）。
- **v1.1.1 收敛**：用户要求下架“下载 App”功能 → 未安装 App 的弹窗只提示“请自行在应用商店下载安装”，保留“用浏览器打开网页版/取消”；移除市场（market://）、官网下载页、相关 `<queries>` 与代码，攻击面进一步减少。
- **残余风险（已记录）**：浏览器打开为隐式 https ACTION_VIEW（已先 resolveActivity 再 setPackage，解析失败才回退；低风险）；自动打开受 Android 10+ BAL 限制（SEC-103）。
- 复制链接（#13）仍未提供；通知点击本身只打开本 App 列表，不自动外跳。

### 3.2 托盘 / 开机自启（#14/#15）

- Android 没有系统托盘；长期后台依赖**前台服务 + 常驻通知**，这也是 Android 对后台监测类应用的合规要求。
- 不做 `RECEIVE_BOOT_COMPLETED`：减少后台启动面、避免“开机自启”类商店审核与用户反感；代价是重启后需用户打开 App 一次。
- 进程被系统回收时 `START_STICKY` 会尝试恢复服务；若用户已关闭监测或系统不允许后台启动前台服务，服务会安全退出而不是崩溃。

### 3.3 v1.1.0 恢复：自定义提示音（#16/#21）

- 通过 SAF 选择文件（**无需存储权限**），复制到应用私有目录（≤2MB，wav/mp3/ogg/m4a/aac，固定文件名 `custom_alert.<ext>`），MediaPlayer 解码校验后使用；不上传、不读其他文件、日志不记路径。
- **风险控制**：2MB 上限、内部副本、固定文件名（无路径穿越）、解码校验、损坏时回退内置 chime；音频内容/版权由用户负责。
- **残余**：MediaPlayer 依赖系统解码器解析不可信音频（已记录 SEC-106）。

### 3.4 置顶弹窗（#17）

- Android 的“悬浮窗”需要 `SYSTEM_ALERT_WINDOW`：属高风险权限（可覆盖其他应用界面），商店审核严格，用户也普遍反感。
- 用 `IMPORTANCE_HIGH` 通知 + 锁屏 `VISIBILITY_PRIVATE` 实现“及时提醒但不打扰、不泄露内容”。

## 4. 行为差异与验收要点

| 维度 | 桌面版 | Android | 验收要点 |
| --- | --- | --- | --- |
| 默认间隔 | 30s | 60s（最短 15s） | 设置页可调；服务每轮重读设置并立即生效。 |
| 请求节奏 | 单线程，房间间 120ms | 单线程，房间间 120ms + 0–2s 随机抖动 | 避免固定节奏打点；失败退避 ×1/×2/×4。 |
| 提醒呈现 | 置顶弹窗（不抢焦点）+ 声音循环 | 高优先级通知 + 渠道音 + 循环音 | 通知锁屏 `VISIBILITY_PRIVATE`；同时最多 4 条。 |
| 提醒动作 | 忽略/不再提醒/打开直播间 | 忽略/不再提醒（点击通知打开 App 列表） | 动作均为显式 PendingIntent（`FLAG_IMMUTABLE`）。 |
| 后台存活 | 托盘常驻进程 | 前台服务 + 常驻通知 | 用户从最近任务划掉后仍继续（`stopWithTask=false`）；通知可暂停/停止。 |
| 省电 | 事件等待，空闲 CPU≈0 | `delay` 挂起 + 短唤醒锁；无网络跳过 | 空闲 CPU≈0；深睡时提醒可能延迟到维护窗口。 |
| 数据存储 | `config.json` + `.bak`（程序目录/AppData） | `SharedPreferences`（应用私有目录） | 卸载即删除；`allowBackup=false` 不进云备份。 |
| 日志 | `logs/app.log` + `app.prev.log` | 应用私有 `files/logs/`（同 1MB 轮转） | 不含 URL/标题/Cookie；可清空。 |
| 开机恢复 | 支持开机自启 | 不支持（需打开 App 一次） | 已知限制，见 `架构与后台省电设计.md`。 |
| 多平台识别 | 链接 host 含平台名 | 精确域名白名单 + 平台枚举 | 拒绝非 http(s) scheme、拒绝搜索页、拒绝抖音短链。 |

## 5. 数据迁移

- **不提供**桌面版 `config.json` 自动导入：两端存储模型、字段与校验规则不同，导入会引入额外解析面；建议用户在 Android 端重新添加（房间号/链接粘贴即可）。
- 未来若需要导入，应实现为“只读导入 + 逐条走 `PlatformApi.normalizeStoredUrl` 校验”的显式流程，并做单独安全评审。
