# 合规评估（Android 版）

> 状态：阶段一文档（2026-11-13）。本文是**工程与安全视角的技术合规评估，不构成法律意见**。
> 关键立场：**不声称已获得任何直播平台的授权/许可**；平台页面访问存在服务条款（ToS）与 robots 协议风险，由使用者自行评估与承担；商用/大规模分发前应做法务复核。

## 1. 应用定位与数据流（合规基础事实）

- 定位：**本地开播提醒工具**。用户主动添加直播间 → App 定时访问对应平台的公开页面/接口判断开播状态 → 本地发通知提醒。**不跳转直播间、不播放内容、不登录、无账号体系、无服务器、无上报。**
- 网络：仅访问斗鱼/虎牙/B站/抖音/快手 5 平台的公开页面/公开接口（HTTPS，精确域名白名单，逐跳重定向校验）。
- 存储：仅本机 `SharedPreferences`（应用私有）+ 应用私有日志；`allowBackup=false`；卸载即删除。
- 权限：INTERNET、ACCESS_NETWORK_STATE、POST_NOTIFICATIONS、FOREGROUND_SERVICE、FOREGROUND_SERVICE_SPECIAL_USE、WAKE_LOCK（共 6 项，无定位/通讯录/短信/存储/相机/悬浮窗/无障碍）。
- 前台服务类型：`specialUse`（本地开播提醒），Manifest 附用途说明 property。

## 2. 个人信息保护（PIPL/隐私最小化）评估

### 2.1 处理的数据类别

| 数据 | 来源 | 是否个人信息 | 处理方式 | 必要性 |
| --- | --- | --- | --- | --- |
| 直播间链接/房间号/快手用户名 | 用户主动输入 | 可识别到具体直播间（非自然人身份） | 提取平台+ID 后重建 URL，本地保存 | 实现提醒所必需 |
| 用户备注名 | 用户主动输入 | 可能含个人信息（由用户决定） | 本地保存，仅本地显示 | 可选功能 |
| 主播昵称、直播标题、分区、开播状态/时间 | 平台公开页面/接口 | 公开信息，但可能关联自然人（主播） | 仅本地展示/提醒/记录 | 实现提醒所必需 |
| 设置项 | 用户设置 | 否 | 本地保存 | 功能所需 |
| 诊断日志 | App 运行 | 否（已脱敏，无 URL/标题/Cookie） | 本地最多约 2MB，可清空 | 问题诊断 |
| 设备标识、位置、通讯录、剪贴板内容、账号、手机号 | — | — | **不收集** | — |

### 2.2 PIPL 要点对照

| 要求 | 本 App 情况 |
| --- | --- |
| 最小必要 | 仅 6 项权限、仅提醒所需字段；无设备标识/位置/通讯录/相册 |
| 告知同意 | 应用内隐私政策 + 首次使用通知权限运行时请求；无隐蔽收集 |
| 目的限定 | 仅用于本机开播提醒；不做用户画像/广告/统计 |
| 本地处理/不出境 | 无服务器、无上传、无跨境传输 |
| 保存期限 | 用户可删除房间/清空日志；卸载即全部删除 |
| 第三方共享 | 无第三方 SDK、无共享/出售 |
| 个人权利（查/删/更正/撤回） | 应用内删除房间、关闭监测、清空日志、卸载；无需账号 |
| 安全措施 | HTTPS、系统 CA、最小权限、私有存储、不备份、日志脱敏 |

**结论**：个人信息处理面很小且全部本地；无需做个人信息出境/第三方共享评估。**风险点在“用户备注/主播信息属于他人信息时的二次使用”**——仅本地提醒用途、不公开传播，风险低；但若未来加入云同步/分享/导出，需重新评估并更新隐私政策。

## 3. 平台访问方式与频率（技术事实）

### 3.1 各平台访问路径（与代码一致）

| 平台 | 主路径 | 降级路径 | 请求/轮/房间（上限） |
| --- | --- | --- | --- |
| 斗鱼 | `GET https://open.douyucdn.cn/api/RoomApi/room/{roomId}` | `GET https://www.douyu.com/betard/{roomId}`（带 `Referer: https://www.douyu.com/`） | 2 |
| B站（房间号） | `GET https://live.bilibili.com/{roomId}`（公开直播间网页） | `api.live.bilibili.com/.../getInfoByRoom` → `room_init` → `get_info`（+可选 `getRoomInfoOld`） | ≤5（含 20 分钟一次首页预热 `https://www.bilibili.com/`） |
| B站（UID） | `api.live.bilibili.com/room/v1/Room/getRoomInfoOld?mid={uid}` | `https://space.bilibili.com/{uid}/live` | 3 |
| 虎牙 | `GET https://www.huya.com/{roomId}` | `GET https://m.huya.com/{roomId}` | 2 |
| 抖音 | `GET https://live.douyin.com/{webRid}` +（页面含 nonce/roomId 时）`https://live.douyin.com/webcast/room/web/enter/?...&web_rid=...&room_id=...` | 页面内嵌 `status` 字段兜底 | 2 |
| 快手 | `GET https://live.kuaishou.com/u/{userId}` | 无 | 1 |

- 所有地址均为 **HTTPS**；请求头固定普通 Chrome UA + `Accept-Language: zh-CN...` + `Accept: */*`（与桌面版一致，**不轮换、不伪造其他设备**）；B站/抖音的匿名 Cookie 仅内存保存（用于降低 412/风控概率，不登录、不持久化、不上传）。
- 不下载视频流/弹幕/评论；不调用需要登录态的接口；不识别/绕过验证码；不使用代理、IP 轮换、UA 轮换、设备指纹伪装。

### 3.2 访问频率

- 检测间隔：**用户可设 15–3600 秒，移动端默认 60 秒**（合规下限 15s 硬编码 `MIN_INTERVAL_SEC=15`）。
- 单线程顺序轮询：同一时刻只有一个平台请求；房间之间 120ms + 0–2000ms 随机抖动。
- 失败退避：连续网络失败 ×1/×2/×4；无网络跳过本轮；HTTP 403/429 只在下一轮常规重试（不加速）。
- 典型量级：10 个房间、60s 间隔 ≈ 每小时 600 次“房间检测”，按每房间 1–3 个请求估算 ≈ **600–1800 请求/小时**（默认设置）；200 房间上限时理论上限更高，但实际使用建议控制在少量房间并调大间隔。
- 该频率远低于浏览器正常使用/平台推荐抓取频率，且无并发突发；是否“合理”最终由平台 ToS 与法务判断。

## 4. robots.txt / 服务条款（ToS）风险声明

### 4.1 robots.txt 抽检记录（2026-11-13 通过本机 web_fetch 抓取，仅为事实记录）

| 站点 | 抓取结果（原文要点） | 对本 App 的含义 |
| --- | --- | --- |
| `https://www.douyu.com/robots.txt` | `User-Agent: *`；`Disallow: /api/*`、`/member*`、`/admin/*`、`/room/*`、`/t/*` | `www.douyu.com/{id}` 与 `/betard/{id}` 不在其通配 Disallow 列表内；但 `/api/*`、`/room/*` 被声明禁止——本 App 的公开 API 请求走 `open.douyucdn.cn`（不同主机，未抽检其 robots），**不能据此宣称合规**。 |
| `https://www.huya.com/robots.txt` | 多个具名爬虫 `Disallow: /api/ /web_api/ /udb_web/ /member/`；末尾 **`User-Agent: *` → `Disallow: /`** | 该站点对通用自动化访问声明了全站禁止（`*` 组）。本 App 以固定浏览器 UA 访问公开页面，**不属于被明确许可的爬虫**；存在被认定为违反 robots 意图的风险。**这是本项目最需要如实告知的平台合规风险**。 |
| `https://www.bilibili.com/robots.txt` | `User-Agent: *` 仅禁止 `/medialist/detail/`、`/index.html`、多语言首页等；`live.bilibili.com/robots.txt` 本次抓取失败（HTTP 404/被拦截），未能核验 | `www.bilibili.com/` 根路径未被通用规则禁止；`live/api` 子域规则未知，**未核验不等于允许**。 |
| `https://live.kuaishou.com/robots.txt` | 仅对 Baiduspider/Googlebot/bingbot 等声明 `Allow: /`；**无 `User-Agent: *` 组** | 按 robots 协议，无匹配组的 UA 默认允许；但站点 ToS 仍可能限制自动化访问。 |
| `https://live.douyin.com/robots.txt` | 本次抓取失败（工具返回 HTTP 404/被拦截），未能核验 | 无法据此判断；抖音风控最严，风险自负。 |

> 说明：robots.txt 不是法律文件，不构成授权；抓取时刻的 robots 也可能随时变化。**本次仅做抽样记录，未逐条核验各平台服务条款/用户协议中的“自动化访问/爬虫/数据使用”条款**。上线前应由项目方（或法务）逐平台复核 ToS。

### 4.2 风险与立场

1. **不声称授权**：本项目与斗鱼/虎牙/B站/抖音/快手无任何合作或授权关系；页面访问属于第三方平台，用户需遵守平台服务条款。
2. **风险自负**：平台可能依据 ToS/robots 限制自动化访问，导致限流、封禁 IP/账号（本 App 不登录账号，通常影响 IP）或法律争议；使用本 App 的风险由使用者承担。
3. **虎牙特别提示**：`www.huya.com/robots.txt` 的 `User-Agent: * Disallow: /` 是明确的通用禁止声明。保留虎牙支持的取舍：仅用于个人本地提醒、低频率（≥15s，默认 60s）、不聚合/不转售/不公开传播数据；若项目方希望更保守，可在未来版本提供“平台开关”由用户自行关闭虎牙监测（当前未实现）。
4. **本 App 的自我约束**：不做验证码绕过、不做代理/IP 轮换、不做 UA 轮换、不模拟登录、不抓取视频/评论、不将数据上传/转售、不提供批量监控/商业监控能力。

## 5. 应用商店与分发合规点

> 补充（阶段三）：新增的 **TLS 证书固定（CA 家族级，默认关闭，可手动开启）** 只是客户端传输层校验的强化，**不改变**本 App 对平台的访问方式、请求频率、User-Agent、Cookie/登录态策略与数据流；因此不改变本文的合规姿态与风险结论（访问频率、robots/ToS 风险仍以第 3、4 节为准）。

### 5.1 v1.1.0 新增功能的合规说明（进入直播间 / 自定义提示音 / 自动打开）

**1) 外部 App / 浏览器跳转（v1.1.1 起不再提供“下载 App”）**

- 仅由**用户主动操作**触发（列表/通知的“进入直播间”按钮、未安装弹窗中的“浏览器打开网页版”）；**默认不自动跳转**（“自动打开直播间”设置默认关闭）。
- 跳转目标仅两类：平台 App（显式包名）、平台官方直播间网页（https 固定域名）。**v1.1.1 已下架应用市场（market://）、平台官网下载页跳转**，未安装 App 时只提示用户自行在应用商店下载安装，不提供任何下载链接。
- **不会**把直播间列表/账号/设备信息传给第三方；跳转后由平台 App/浏览器按其自身隐私政策处理，本 App 不采集其数据。
- **包可见性最小化**：`<queries>` 仅 5 个平台包 + https VIEW intent（解析系统默认浏览器），**未申请 `QUERY_ALL_PACKAGES`**，也无 market 查询。
- **商店政策提示**：外部跳转属于常规用户操作；自动打开默认关闭，避免“后台自动拉起应用/广告”类政策风险。浏览器跳转先解析系统默认 handler 再显式启动，仅解析失败时回退隐式（SEC-101 残余已随下载功能下架进一步缩小）；不属于平台数据合规问题但应在安全说明中告知。
- 不改变监测访问频率、UA、Cookie 与 robots/ToS 姿态（第 3、4 节结论不变）。

**2) 自定义提示音**

- 用户通过系统文件选择器（SAF）主动选择本机音频；App **不申请存储权限**，只把文件复制到应用私有目录（2MB 上限、固定文件名），仅用于本地通知提示音；不上传、不分享、不扫描其他文件；用户可随时恢复内置音/删除。
- 合规要点：用户选择的音频文件内容由用户负责（版权/内容）；应用不解析元数据、不写入日志；卸载即删除。

**3) 自动打开直播间**

- 设置默认**关闭**，需用户显式开启；仅对手机端新提醒尝试一次；受 Android 10+ 后台启动限制（BAL），可能不生效（见安全报告 SEC-103）。不申请悬浮窗/电池白名单等权限绕过系统限制。

**4) 动态验证说明（v1.1.0，LDPlayer 14）**

- 进入直播间已实测（v1.1.0，v1.1.1 将复测）：App 优先（B站 App 直达）、未安装 App 弹窗、浏览器网页版、通知「进入直播间」动作；跳转目标均为固定平台地址，App 未向第三方传递房间列表/账号/设备信息。**v1.1.1 起未安装弹窗不再提供下载 App/应用市场/官网链接，只提示用户自行下载并保留“浏览器打开网页版/取消”。**
- 包可见性实测与静态一致：仅声明 5 个平台包 + https VIEW intent（浏览器解析）；无 QUERY_ALL_PACKAGES、无 market 查询。
- 自定义提示音导入/试听/播放路径已验证（文件仅存应用私有目录）；未上传、未读取其他文件。

**5) 签名与分发**

- 交付 APK 已签名（v2+v3、非 debug 证书）；签名密钥在本地 `android/keystore/` 与 `android/keystore-backup/`（均 gitignore、不入库）。备份包含 keystore+口令，属高度敏感资料，必须离线保管、不得上传/随包分发；公开分发建议组织自有密钥重签并同步替换备份。详见 `安全测试报告.md` 与 `README.md` 签名章节。

## 6. 平台访问频率合规的最低要求（作为项目约束）

- 硬编码间隔下限 **15 秒**（`AppSettings.MIN_INTERVAL_SEC`），UI 不可设置更低。
- 单线程顺序 + 房间间乱序间隔；禁止并发突发。
- 失败退避，禁止失败后立即重试；HTTP 403/429/412 不绕过、不换 IP/UA。
- 不提供“批量导入大量房间”的自动抓取脚本；房间上限 200，建议用户按需添加。
- 未来若增加平台/接口，须先通过本评估流程（访问方式、频率、robots/ToS、是否需登录、是否触碰风控）。

## 7. 结论

| 维度 | 结论 |
| --- | --- |
| 数据合规（PIPL/最小化） | **低风险**：无服务器、无上报、无账号、权限最小、本地存储、可删除；隐私政策草案已备。 |
| 商店合规 | **基本满足**：无敏感权限、FGS specialUse 需申报、通知权限规范、不滥用电池白名单；需补隐私政策链接与 Play 数据安全表单。 |
| 平台访问合规 | **存在残余风险，需明确告知**：虎牙 robots 对 `*` 全站 Disallow；抖音/B站 live 子域 robots 未能核验；未逐条核验 ToS。**不得声称已获授权**；使用者风险自负；商用/大规模分发前应做法务评估，必要时调整平台支持范围。 |
